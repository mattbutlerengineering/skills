# Architecture: Codex-style standards enforcement

## Approach

Four additions on top of unchanged existing machinery, sized to reuse
rather than duplicate: (1) a derived JSON index, regenerated by one new
stdlib script from a new ADR section convention; (2) enforcement status
carried entirely as a field in that index, so promotion is a one-line
JSON diff, never an ADR edit; (3) the base `review` skill, the
`factory-reviewer` charter, the `architect` skill, and the
`factory-architect` charter each gain a short "load the filtered index,
cite slugs" step, no restructuring; (4) one new gate-detector check for
`defect.md` completeness, modeled directly on the section-scanning
detector H already applies to `verification.md`. Nothing here is a new
kind of thing this repo doesn't already have one of — a derived,
checksum-pinned artifact (like `factory/manifest.json`), a seam module
imported by both a writer and a gate detector (like `cost_ledger.py`),
and a status vocabulary already living in a JSON field this repo
already treats as the single source (`factory.json`'s config, ADR-0004).

## Components

### 1. The normative-statement index (`docs/standards.json`)

- **Responsibility:** hold the derived, regenerable list of normative
  statements: `{slug, statement, level, source, status, domain}`.
  `level ∈ {MUST, SHOULD}`; `status ∈ {advisory, enforced}`;
  `domain ∈ {factory, pipeline, eval, docs}` (issue #448's own shape).
  `source` is either `adr/NNNN#<slug-anchor>` (an ADR's `## Normative
  statements` bullet) or `CLAUDE.md#<anchor-text>` (a hand-curated
  entry — see Decisions below for how that resolves without a
  heading-anchor convention CLAUDE.md doesn't have).
- **Collaborators:** written by `standards_index.py`'s regen verb;
  read by the new gate detector, the `review`/`architect` skills, and
  the `factory-reviewer`/`factory-architect` charters (the latter four
  read it directly as data — a skill or charter is prose an agent
  follows, not a Python caller, so "loading" it means reading the
  file, filtering by `domain`, never importing anything).
- **Source convention (new, going forward only):** an ADR MAY carry a
  `## Normative statements` heading with one bullet per statement:
  `- **<slug>**: <one sentence containing exactly one of
  MUST/MUST NOT/SHOULD/SHOULD NOT>`. This is the only mechanically
  extracted source. Existing ADR prose and CLAUDE.md's existing
  "Hard conventions" bullets are NOT mined — back-filled by hand only
  where judged worth enforcing, matching the issue's own "back-fill
  only statements worth enforcing, not exhaustively." Full NLP-style
  extraction from free prose was considered and rejected below.

### 2. `standards_index.py` (new root module)

- **Responsibility:** the shape/parsing/regeneration seam — the CLAUDE.md
  "seam modules, everything else thin callers" convention applies here
  exactly as it does to `cost_ledger.py`: this module owns the
  statement shape, the enum vocabularies, the `## Normative
  statements` bullet grammar, and the regeneration algorithm (scan
  `docs/adr/*.md`, rebuild the ADR-derived subset, leave any entry
  whose `source` starts with `CLAUDE.md#` untouched, fail loudly on a
  slug collision between the two). A CLI front door
  (`python3 standards_index.py update`) mirrors `factory_init.py
  update-manifest`'s verb shape exactly — same "regenerate, diff,
  write" pattern, same stdlib-only constraint.
- **Why a new module and not logic folded into `gates.py` directly:**
  the shared-module bar (CLAUDE.md: multiple real callers AND observed
  divergence, not anticipated reuse) is met on day one, not
  speculatively — the regen script must validate what it writes and
  the gate detector must independently re-validate the committed file
  against a fresh regen; those are two real call sites that need the
  same shape/parsing logic simultaneously, the same relationship
  `cost_ledger.py` already has with `gates.py`'s detector G.
- **Collaborators:** imported by `gates.py` (the new detector) and run
  standalone via `factory.py standards-index` once `factory.py`'s
  `VERBS` table picks it up (mechanically pinned by
  `tests/test_factory_cli.py`'s scan of CLI-bearing root modules — no
  hand-edit needed beyond adding the module and its `main()`).
- **Payload treatment — the question this PRD's architecture explicitly
  asked:** YES, this ships. `gates.py` is mirrored into every
  factory-stamped product repo via `factory_init.MIRRORS` (identity
  transform, `tools/factory/gates.py`), and if the new detector lives
  in `gates.py` and imports `standards_index`, that import must resolve
  in the stamped repo too. So `standards_index.py` gets its own
  `MIRRORS` entry (`("standards_index.py",
  "tools/factory/standards_index.py", identity)`), same as
  `cost_ledger.py`/`human_gates.py`/`knowledge_plane.py` — and
  `factory_init.py update-manifest` must be re-run and
  `factory/manifest.json` committed in the same PR that adds it
  (detector E gates this; `CLAUDE.md`'s "Factory templates are
  checksum-pinned" rule is unchanged, just gaining one more mirrored
  file). This is the same reasoning CLAUDE.md already states for why
  `plane_drift.py` stays root-only — it ships *iff* a payload tool
  imports it, and here one will.
- **`docs/standards.json` itself is NOT mirrored as a template.** It is
  per-repo derived data, exactly like `docs/factory/costs.jsonl` is
  never templated — a product repo generates its own from its own
  ADRs/CLAUDE.md by running the shipped script locally after stamping,
  the same way it customizes its own `factory.json` rather than
  inheriting the skills repo's.

### 3. The new gate detector(s) in `gates.py`

- **Responsibility:** two independent mechanical checks, kept as two
  detectors rather than one combined check (matching this repo's
  one-concern-per-letter convention — A/B/C/D/.../I each check exactly
  one thing):
  - **`K` — `STANDARDS-DRIFT`:** (a) regenerating the ADR-derived
    subset of `docs/standards.json` via `standards_index.py` and
    diffing it against the committed file fails the same way detector
    E's checksum-pin does for `factory/manifest.json`; (b) any entry
    with `status: enforced` whose `source` names an ADR whose
    `ADR_STATUS` is not `accepted` fails — reusing `gates.py`'s
    existing private `_adr_status`/`ADR_STATUS` machinery directly
    (the same status vocabulary detector D already owns; this is an
    extension of D's invariant to a new source type, not a second
    status vocabulary — CLAUDE.md's "second source of truth" rule cuts
    the other way here: reusing `_adr_status` avoids creating one).
  - **`M` — `CAPTURE-COMPLETENESS`:** every `docs/fixes/<slug>/
    defect.md` carries the protocol's required sections (Defect/
    Condition, Reproduction/Evidence, Root-cause hypothesis, Blast
    radius, Ruled out — `skills/capture/TEMPLATE.md`'s own headings),
    each non-placeholder, using the section-splitting machinery
    (`HEADING_LINE`, the setext-title handling) detector H already
    built for `verification.md` — generalized to take a required-
    heading list as a parameter rather than duplicated.
- **Why `gates.py`, not `lint.py` (PRD's Open question, resolved
  here):** `lint.py`'s checkers are unmirrored and specific to this
  meta-repo's own plugin/skill authoring (`SKILL.md` files, protocol
  tables, `LEDGER.md`) — they would be meaningless in a product repo
  that merely uses the pipeline to build its own product. `gates.py`'s
  detectors are exactly the ones that DO ship to every factory-stamped
  product repo and already gate the knowledge plane generically
  (`WO-CITATION`, `LINK-INTEGRITY`, `BLUEPRINT-DRIFT` apply to any
  repo's own PRDs/ADRs, not just this one's). Both the standards index
  and `defect.md` completeness are exactly that kind of generic,
  any-repo concern — issue #448's own text calls for a "gate detector"
  for index drift specifically, and `defect.md` completeness is the
  same shape of check as `verification.md`'s (already `gates.py`-
  homed, detector H). So: both live in `gates.py`.
- **Letters `K`/`M`, not `J`/`K` (a decision, not a default):** `J`
  already carries a fully-written docstring entry (`LABEL-WIRING`) for
  unrelated in-flight work on `feat/first-live-dispatch` (WO-0039,
  unmerged as of this design). Claiming `J` here would hand a human
  two competing claims on the same letter to reconcile by hand — an
  avoidable collision. `L` is already `LABEL-SYNC`. `K` is genuinely
  free; a second new letter skips straight to `M` rather than reusing
  `L` or waiting on `J`. `gates.py`'s own docstring already says "the
  letter namespace does not end at I" — non-contiguous letters are an
  accepted existing pattern (`L` already breaks contiguity), not a new
  irregularity this design introduces.
- **Selftest coverage:** both new detectors get planted-defect fixtures
  under `python3 gates.py --selftest`, per the existing convention
  every lettered detector already follows.

### 4. Standards-aware review and blueprint gate (skill + charter prose)

- **Responsibility:** four prose-only changes, no new Python:
  - `skills/review/SKILL.md` — a new step: before ranking findings,
    load `docs/standards.json`, filter to statements whose `domain`
    matches the diff's touched paths (a `factory/**` or root-tool
    change pulls `domain: factory`; a `docs/**`/skill-body change pulls
    `domain: pipeline`/`docs`), and cite any matching slug a finding
    bears on. An `enforced` MUST finding is not a "minor to defer" —
    Review's existing fix-loop rule (critical findings fixed before
    Ship) now applies to any unresolved `enforced` finding the same
    way, without changing what "critical" means for anything else.
  - `factory/charters/reviewer/CHARTER.md` — the same load-and-cite
    step added to "Actions per cycle," and one line in "Must never":
    an unresolved `enforced` finding blocks the pass verdict the same
    way an open security finding already does (the charter's existing
    "Approve-with-nits when any security finding is open" rule gets a
    sibling clause, not a rewrite).
  - `skills/architect/SKILL.md` and `factory/charters/architect/
    CHARTER.md` — a step before drafting: load the index filtered to
    `domain ∈ {factory, pipeline}` (the design-relevant slice — the
    issue's "spec reviewer" scaled down), and cite any statement the
    design's decisions bear on in `architecture.md`'s own "Decisions"
    section, the same way this very document cites ADR numbers today.
- **Collaborators:** reads `docs/standards.json` directly (data, not a
  Python import — skills and charters are agent-followed prose).
- **Deliberately NOT touched:** the `factory-planner` charter (Decompose
  isn't a review/design-gate stage — issue #448 names review and the
  blueprint gate specifically, not Decompose), and `review.md`'s/
  `architecture.md`'s `TEMPLATE.md` files gain a slug-citation line but
  keep every existing section — no restructuring of either template.

## Data model

`docs/standards.json` — a JSON array, sorted by `slug` for stable
diffs (the same stability concern `factory_init.py update-manifest`
already has for `factory/manifest.json`):

```json
[
  {
    "slug": "adr0032-one-way-mirror",
    "statement": "A work-order issue MUST be created only after its breakdown row exists.",
    "level": "MUST",
    "source": "adr/0032#one-way-mirror",
    "status": "enforced",
    "domain": "factory"
  }
]
```

No new run-artifact typed ID, no parallel `docs/` tree (ADR-0004): the
`source` field points AT the ADR/CLAUDE.md passage; the ADR stays the
decision of record, the index is a derived view. `slug` is stable and
human-assigned at the point a statement is written into an ADR's `##
Normative statements` section (or, for a CLAUDE.md back-fill, chosen by
whoever adds the entry) — never regenerated from content, so a slug
survives an ADR's prose being lightly reworded.

## Interfaces & contracts

### `standards_index.py update`

- Input: `docs/adr/*.md` (scanned for `## Normative statements`
  sections), the current `docs/standards.json` (for its hand-curated
  `CLAUDE.md#`-sourced entries, preserved verbatim).
- Output: a rewritten `docs/standards.json` whose ADR-derived entries
  are freshly regenerated and whose CLAUDE.md-derived entries are
  unchanged; a nonzero exit if a regenerated slug collides with a
  hand-curated one.
- Failure modes: a malformed `## Normative statements` bullet (no
  slug, no RFC-2119 keyword, more than one keyword) is a problem
  string, not a silent skip — mirrors `check_wo_citation`'s "declared,
  never assumed" discipline.

### Gate detector `K` (`STANDARDS-DRIFT`)

- Input: committed `docs/standards.json`, a fresh in-memory regen via
  `standards_index.build_index(root)`, `docs/adr/README.md`'s status
  table (via the existing `_adr_status` helper).
- Output: label-prefixed problem strings (`K: docs/standards.json
  drifted from a fresh regeneration — run standards_index.py update`;
  `K: enforced statement <slug> cites ADR-NNNN, status <status> (not
  accepted)`), same contract every other detector already returns.
- Failure modes: an absent `docs/standards.json` is not a K problem —
  same "an absent ledger is silent" precedent detector G already
  sets (no runs recorded yet is not a violation); the index existing
  and disagreeing with source is the violation.

### Gate detector `M` (`CAPTURE-COMPLETENESS`)

- Input: every `docs/fixes/<slug>/defect.md` `run_dirs()` finds.
- Output: `M: docs/fixes/<slug>/defect.md missing required section
  'Blast radius'` (one problem string per missing/placeholder
  section), same contract as H.
- Failure modes: a run with no `defect.md` yet (idea/PRD-only feature
  runs, or a maintenance run mid-Capture) is out of scope for this
  check entirely — M only walks `docs/fixes/*/defect.md` paths that
  exist, the same "absence elsewhere is not this detector's problem"
  discipline C already applies file-by-file.

## Stack & dependencies

- Stdlib only (`json`, `re`, `pathlib`) — no new dependency, matching
  the hard convention every other root module already follows.
- No new GitHub Actions workflow: both new detectors run inside the
  existing `make check` / `validator.yml` invocation of `gates.py`,
  same as every other lettered detector.

## Decisions & alternatives

- **New module (`standards_index.py`) over folding regen+validation
  straight into `gates.py`** — folding it in loses the "one seam, two
  real callers" property (the CLI regen script would either duplicate
  the parsing logic or `gates.py` would need its own CLI verb, which
  `factory.py`'s router explicitly resists: "A ROUTER, NOT A SEAM").
  Matches `cost_ledger.py`'s precedent exactly.
- **Enforcement status lives in the index, not in ADR prose** — the
  alternative (editing an ADR's status line, or its body, to say
  "enforced") loses because ADRs are append-only/supersede-only
  (CLAUDE.md); forcing every promotion through a new ADR would turn a
  one-line evidence-backed status flip into ADR churn disproportionate
  to the decision. The index field is the smaller, more reversible
  surface — and reversibility is exactly what this repo's ADR bar
  (architect charter: "an ADR for each decision that is expensive to
  reverse") says should NOT need a new ADR.
- **`K`/`M`, skipping `J`** over claiming `J` for one of the two new
  checks — `J` already has a fully-written docstring commitment
  (LABEL-WIRING) from unmerged in-flight work; claiming it here creates
  a real collision a human would have to resolve by hand across two
  unrelated PRs. Skipping costs nothing (letters are just labels, not
  contiguous by any enforced rule) and removes the collision entirely.
- **Two detectors (`K`, `M`) over one combined detector** — a single
  "standards" detector checking both index drift and `defect.md`
  completeness would violate this repo's own one-concern-per-letter
  convention (A through I each check exactly one thing) for no
  savings — the two checks share no code and fail for unrelated
  reasons; combining them would make failures harder to triage, not
  easier.
- **No mechanical extraction from existing ADR prose or CLAUDE.md** —
  considered and rejected. A regex/NLP pass over free-form English for
  implicit MUST/SHOULD sentences would produce both false positives
  (any sentence containing "must" as an ordinary word) and false
  negatives (a real rule phrased without the keyword), and — worse —
  would silently misattribute enforcement to a statement nobody
  deliberately chose to index. A new, explicit, opt-in heading
  convention is the smaller, more honest surface; it costs "existing
  ADRs aren't retroactively indexed," which the issue's own scoping
  already accepts ("back-fill only statements worth enforcing, not
  exhaustively").
- **No real `docs/adr/**` file authored by this run** — the
  architect-charter convention is to write an ADR for every
  hard-to-reverse decision, and several choices above (module split,
  detector-letter choice, status-in-index-not-ADR) plausibly clear that
  bar. This run does not author one anyway: minting a real ADR file is
  itself a gate-2 blueprint action (ADR-0033) with no human available
  to approve it in this session, and a placeholder number would trip
  detector C the moment any other in-flight work claims the next real
  number first. Recorded here, in this architecture document, per the
  same "the cap dance is fully reversible and recorded here... a
  one-line record suffices" pattern `first-live-dispatch`'s
  architecture.md used for a comparable case. breakdown.md carries an
  explicit work item to author the real ADR(s) once a human has
  actually approved this design.
- **No tracker mirror issues created by this run's Decompose pass** —
  ADR-0032's one-way rule and the planner charter both presume a
  blueprint has already passed the human blueprint gate before rows
  become dispatch-ready; this design hasn't been through that gate.
  Mirroring now would let the dispatch plane run ahead of an unapproved
  blueprint, which is the exact ordering ADR-0032 exists to prevent.

## Traceability (PRD-0004 criterion → component)

Index shape/regen script → Component 1+2; drift + supersession
detector → Component 3 (`K`); selftest coverage → Component 3; review
skill + reviewer charter citation/blocking → Component 4; architect
skill + architect charter design-relevant loading → Component 4;
`defect.md` completeness checker → Component 3 (`M`); battery stays
green → every component (no existing detector, checker, or test is
modified, only new ones added); no parallel docs tree → Component 1's
`source`-points-at-original design, checked by `K` itself.

## Follow-on work this design deliberately does not include

- Authoring the real `docs/adr/**` file(s) this design implies, once a
  human has approved it (see Decisions above).
- The advisory→enforced promotion of any specific statement (PRD-0004
  Out of scope; breakdown.md flags this explicitly as needing a human
  decision rather than being scriptable at implementation time).
- Extending the index/detector pattern to `oh-my-pi`/omp packaging —
  out of frame; the skill/charter prose stays harness-neutral either
  way per the protocol.
