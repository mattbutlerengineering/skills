# Architecture: Judge the same-call heredoc body

## Approach

Inside the one parse the hook already does, record each statement-level heredoc's text instead of discarding it, keep each simple command's redirections and the operator that joined it, and, when a `gh pr create --body-file F` is not the compound's first command, search the earlier simple commands for the writer of F and then check the commands around it in fixed passes over the same records (shipped as `_bound_body`; the first draft described a *ledger* built by one forward walk, which was not built, see Amended 2026-11-09). A file is *bound* to its heredoc text when exactly `cat > F <<D` wrote it, unconditionally, and nothing in between may have changed what F names or holds, and nothing before the writer opens a descriptor onto F or redefines the commands that run. A bound F is judged through `gates.pr_body_problems` exactly as a body file read from disk is today; every other outcome raises `_Unreadable` with a reason, which is the hook's existing "not checked" note and exit 0. The binding reads no file, so it is pure and adds no I/O, timeout or side effect of its own.

The second shape considered was to actually run the heredoc part of the command in a sandbox at hook time and read back the file a real shell wrote. It would be exactly the oracle the PRD uses at Verify, but a hook that executes shell text has side effects and a start-up cost on every `gh pr create`, and it makes the hook's own safety depend on the sandbox. It stays a Verify-time oracle only. The third shape was a standalone `heredoc_binding.py` module; see Decisions.

## Components

### Heredoc capture (`_Unrun`, extended)

- Responsibility: today it cuts every heredoc body and comment so neither is tokenized as a command, and throws the bodies away. It now also records, per statement-level heredoc, `(text, literal, terminated)` and rewrites that heredoc's operator-plus-delimiter into `<<` followed by an indexed placeholder word (the existing `PLACEHOLDER` convention: `__pr_body_preflight_heredoc_<N>__`, `N` counting heredocs `_Unrun` queues, in queue order). `text` is the bytes a shell writes (each body line plus a newline; leading tabs stripped for `<<-`). `literal` is true when any part of the delimiter word was quoted or backslashed, or when the body holds no `$`, backtick or backslash (the rule `_heredoc_at` applies to `$(cat <<D`); it is computed on the unmasked text, after each `_mask_heredocs` placeholder in the body is restored, so a body that holds a `$(cat <<'B' … B)` snippet is judged on the original span. `<<<` is a here-string, not a heredoc: it queues nothing and gets no index.
- Unmasking: `_mask_heredocs` runs first on the raw string and rewrites any `$(cat <<'B' … B)` it finds, including one that sits inside a statement-level heredoc body (a PR body that documents this very hook). The capture therefore restores each placeholder it finds in a captured body to the original span, which `_mask_heredocs` now returns as `(placeholder, original)` pairs. The file text is then the text the shell would write. This settles review finding 8 without changing what the tokenizer sees.
- Two more things the capture does. A digit word that touches its `<` or `>` in the unquoted source (a descriptor prefix: the `2` of `2>&1`) is replaced by a marker word (`FD_PREFIX`, `_Unrun._fd_prefix`) so the splitter can write the digits into the operator (`2>&`, `3<<`); a digit a space away (`2 >&1`, `5 < x`), a quoted or escaped one, `x2>&1` and `$2>&1` stay ordinary words, and `>&` or `<&` followed by digits never marks its target (`2>&1>F` is the duplication, then `> F`). And `_Unrun.ansi_c` is set only when its real ANSI-C branch cuts an unquoted `$'...'` string, so `'costs $'` and a `$'` in a comment or a heredoc body do not set it.
- Collaborators: `_tokens`, `_mask_heredocs`, the binding. The `$(cat <<'D' … )` path keeps its own placeholders and is unchanged.

### Command splitter (`_simple_commands`, extended)

- Responsibility: today it returns word lists and drops each redirection with its target, and drops a command with no words. It now returns one `Simple` per command, including a redirect-only command such as `> /tmp/b.md`: `words`, `redirects` (an ordered list of `(operator, target)`, where a heredoc redirection's target is the placeholder word, from which the index is read, never counted) and `joiner` (the whole shlex punctuation run that precedes it, e.g. `&&`, `&&\n`, `;\n`, `&\n`, `\n`; see Data model). `&>` and `&>>` are redirections. A `<(` or `>(` run anywhere is recorded as a redirection of kind `procsub`.
- `first` and `position` are computed over the `Simple` records that have words, so a leading `> log` does not make a first-command body file "not first" (review finding 10): today's behaviour is preserved, and the word-less record exists only for the binding walk, where a truncation of F is a redirect to a file.
- Descriptor prefixes: a marker word that touches its operator is not a word of the command; its digits join the operator (`2>&`, `12<`), so `2>&1` between writer and reader is a duplication, not a command named `2`, while `2 >&1` and `5 < x` stay a command named by its digit (a note by that verb). The note text writes the digits back (`_unmark`).
- Collaborators: `_verdicts`, the binding. `_working_directory`, `_gh_repo` and `_create_args` read `words` of records with words and are otherwise unchanged.

### Heredoc binding (`_bound_body`, new, in `pr_body_preflight.py`)

- Responsibility: the one owner of "which heredoc wrote the file this `gh pr create` will read, and is that still true". It owns the writer shape, the spelling rule, the chain rule, the invalidation rules and the inert list. Nothing else in the hook knows those rules. It binds on identical spelling and invalidates on anything that might touch a file, which is the fail-closed direction in both halves. As shipped it is `_bound_body(spelling, context)` plus small pure helpers (`_writer_of`, `_comparable`, `_surely_ran`, `_opens_descriptor`, `_shadows`, `_write_redirect`, `_running_redirect`, `_inert`); there is no ledger object. It makes one backward search for the writer and then separate passes over the same `Simple` records, each raising the first reason it finds, in this fixed order: (1) the spelling rule; (2) the writer search, from the reader backwards, so the latest writer of that exact spelling wins; (3) the writer's `terminated` and `literal` flags; (4) the chain rule, over the records from the writer (exclusive) through the reader (inclusive); (5) the `$'` guard; (6) the before-the-writer rules over every record before the writer; (7) rule 1 and the running-redirect part of rule 4 over every record from the writer (exclusive) through the reader (inclusive); (8) rule 1 over the closers after the reader; (9) rule 4 and the `cd` rule over each command strictly between writer and reader. The order fixes which reason a note names when two apply.
- Collaborators: the splitter's records, the capture's heredoc list (`unrun.heredocs`) and its `ansi_c` flag, all handed in through the `context` mapping `_verdicts` builds, and `_body`, its only caller. Source dependencies point toward policy: the binding imports nothing; `gates.pr_body_problems` still sees only a string.
- Deviation, recorded: the first draft had the walk build a `Ledger` (a map from spelling to `Live`/`Dead`) and `_bound_body(commands, heredocs, position, spelling)`. The Implementer built the passes above instead and the Notes never said so; the reason was not recorded. What can be said from the code: one reader looks up one spelling once, so a map had no second user, and a `Dead(reason)` entry is the same fact as the `_Unreadable` the first failing pass raises. The behaviour the Ledger promised (a pure function of the command string, linear in the compound, no I/O) holds.

### Body source (`_body` / `_read_body_file`, changed)

- Responsibility: unchanged in kind: pick the one body source of a `gh pr create` and return its text or raise `_Unreadable`. A `<(` or `>(` anywhere in the reader's own command raises `_Unreadable` before anything else (review finding 2: the splitter reads `-F <(cat a c)` as the file `a`). Then, for a `file` source that is not `-` and not the compound's first command, `_body` asks the binding; `--body-file -` goes to `_read_body_file` first and is always the stdin note, never a bound body. The binding's first step is the spelling rule, so an uncomparable F is reported as such even when no writer exists; only after that does the old reason (`a body file is read only from the first command`) come back, raised when no writer of that exact spelling precedes the reader.
- Collaborators: the binding, `cli.read_file` (disk reads for a first-command file, unchanged).

### `gates.pr_body_problems` (policy, unchanged)

- Responsibility: B's one statement of the body rule. This run adds no caller-side copy of any pattern, so `TestOneOwner` and `one_owner.py` still pass without edit.

### Fixture tests and the Verify replay

- Responsibility: `tests/test_pr_body_preflight.py` gains a `TestSameCallHeredoc` class of full-payload fixtures, in the style of `TestHeredoc` and `TestBodyFile`. The replay and the false-block oracle are Verify's, run against a frozen snapshot (see Interfaces and Decisions).
- Collaborators: `preflight()` only; the fixtures go through the same pure seam as every existing test.

### `docs/kb/pr-body-contract.md` and the module docstring

- Responsibility: say what is now read. The kb page's one-paragraph description of the hook gains the same-call heredoc as a readable shape; the page's `verified:` is refreshed by the author of the change and `kb.py drift` stays clean. No new page.
- Collaborators: `kb.py`, `lint.py`.

## Data model

There is no storage; no run of the hook leaves state behind. The records live for one `preflight()` call.

- `Heredoc`: a `collections.namedtuple("Heredoc", "text literal terminated")`: `text: str` (the bytes a shell writes, unmasked), `literal: bool`, `terminated: bool`, indexed by the placeholder number `_Unrun` assigned (`unrun.heredocs`). The `$(cat <<'D' …)` substitutions keep the separate `(text, literal)` pairs `_mask_heredocs` returns.
- `Simple`: a `collections.namedtuple("Simple", "words redirects joiner")`: `words: list[str]`, `redirects: list[(op, target)]`, `joiner: str`.
- `context`: the per-reader mapping `_verdicts` builds: `first`, `cwd`, `heredocs`, `commands` and `position` (word-bearing commands and the reader's index among them), `records` and `record` (all `Simple` records and the reader's index among them, which differs from `position` when a redirect-only record sits earlier), `statements` (`unrun.heredocs`), `ansi_c`, `prefix` and `environ`.
- There is no `Ledger`. No per-spelling map is built; the writer is found by a backward search and invalidation is a set of passes over `records`.

Access patterns, from the PRD: (1) at one `gh pr create`, "what text does this spelling stand for here?" (one search for the writer); (2) for each earlier simple command, "may this change what the spelling names or holds?" (a constant number of passes, each linear in the compound). Consistency: none beyond a single process; the binding is a pure function of the command string, with no clock, disk or environment.

**The joiner.** shlex with `punctuation_chars` returns a run of punctuation characters as one token (`&&`, `&&\n`, `;\n`, `&\n`, `\n)\n`, `&>`), and whitespace and comments split what a shell reads as one operator into several tokens (`&& ` then a newline, `&& # c` then a newline, `|| ` then a newline). So a record's **effective joiner** is *all* punctuation runs since the previous record that has words or redirects, concatenated in order. A run is a *separator* run when it holds no `<` or `>`. A mixed run is split at its first `<` or `>`: the part before is joiner, the rest is a redirection (`;>` is joiner `;` then redirect `>`; a lone `&` directly before `>` is not split off as a background joiner but kept as part of `&>` / `&>>`; a lone `> F` on its own line after a newline is the joiner `\n` and a redirect-only record). `<`, `>`, `&>`, `&>>`, `>&`, `<>` and `>|` are redirections with their target. Over the effective joiner: `|` (so `||` too), `(`, `)`, or an `&` that is not part of an `&&` pair makes it **hostile**; the rest (`;`, `&&`, newline, in any combination such as `;\n`, `&&\n` or `&& ` newline) is **sequential**. So `&& ` then newline is sequential, `|| ` then newline is hostile, and `&& # c` then newline is sequential (a comment is cut before tokenizing); anything containing a lone `&` (`&`, `&\n`) is hostile, so a background writer never binds. This is defined over the real runs, not over a membership list.

**The writer shape.** A simple command is a writer of F when its words are exactly `cat`, and its redirects are exactly one `>` (target F) and one heredoc (placeholder index), in either order: `cat > F <<D` or `cat <<D > F` (`_writer_of` keys the two redirects by their exact operator). `>>`, `>|`, `&>`, a file-descriptor prefix (`cat 1> F <<D` and `cat > F 3<<D` are not writers), `tee`, `cp`, any other verb, a second redirection of any kind and a heredoc with `terminated` false are not writers. A later writer of the same spelling replaces an earlier one. The writer's own record decides the pairing: its heredoc is the index in its own redirect target, so a `<<` that sits in a `"$( … )"` word (which `_Unrun` queues but shlex keeps inside one word) or in `X=$(sed q <<A …)` (a command whose words are not `cat`) never pairs with a reader.

**The spelling rule.** F is a spelling the hook can compare when:

- it holds no backtick, no `$(`, no glob character (`*?[]`), no brace outside a `${NAME}` form and no leading `~`;
- every `$` in it begins `$NAME` or `${NAME}`, with `NAME` of the form `[A-Za-z_][A-Za-z0-9_]*` and not one of the names a shell changes without an assignment (`SHELL_MAINTAINED`): `RANDOM`, `SRANDOM`, `SECONDS`, `EPOCHSECONDS`, `EPOCHREALTIME`, `LINENO`, `BASHPID`, `PIPESTATUS`, `HISTCMD`, `DIRSTACK`, `status`, `pipestatus`, `PWD`, `OLDPWD`, `_`, or any name beginning `BASH`. `$$`, `$!`, `$?`, `$-` and positional parameters are not `NAME` forms and so are rejected.

The rule is the first thing `_bound_body` checks, before any writer search, so a not-first `-F $PWD/b.md` or `-F ~/b.md` with no writer at all now gives the expansion note, not the first-command note (exit code unchanged). The tokenizer cuts `$(` after its `$`, so `-F $(mktemp)` reaches the rule as `$`; a spelling that ends in `$` gets its own reason, `a command substitution names the body file, which the hook cannot compare`.

F is **absolute** only when it starts with a literal `/`. Anything else, including `$S/b.md`, `${PWD}/b.md` and `./b.md`, is treated as relative to the working directory: a `cd`, `pushd` or `popd` between writer and reader unbinds it. Two words bind when their spelling is identical. The hook never resolves `$NAME` to a value: the same token in the same shell state names the same file whatever its value, including unset.

**Invalidation is fail-closed and never compares spellings.** Binding may rely on identical spelling because a mismatch there only falls back to a note. Invalidation may not, because a missed second spelling (`./b.md` for `b.md`, a `$BODY` alias, an appended `>> "$BODY"`) keeps a stale binding alive. So a bound F is unbound by the first command between the writer (exclusive) and the reader (inclusive of the reader's own redirects) that:

1. carries any redirect whose operator writes (`>`, `>>`, `>|`, `&>`, `&>>`, `<>`, a `<<` or `<<<` with a descriptor prefix, and `>&` followed by a word) unless it is exempt. Exempt: an unprefixed read operator (`<`, `<<`, `<<<`, `<&`) or a prefixed `<` or `<&`; a target of `/dev/null` or `/dev/stderr` for an unprefixed operator, and for a prefixed `>`, `>>` or `>|`; for `>&` only, with or without a prefix, a target of all digits or `-` (a duplication or a close: `>&2`, `2>&1`, `>&-`). `>& F` writes F and unbinds; this covers a redirect-only truncation and every spelling of F, with no comparison. A descriptor prefix is judged by this operator test and by nothing else: `2>&1`, `2>/dev/null` and `2<&0` are judged; `2>F`, `3<>F`, `3<<D` and `1>&2 > F` are notes. The same test (`_write_redirect`) runs on a closing `}`, `done`, `fi` or `esac`, or a record whose joiner holds `)`, **after** the reader: a block redirect closing after the reader redirects what the block wrote, so `} > F` unbinds, while `} > /dev/null`, `} 2>&1` and `} 2>/dev/null` are judged (the closer rule uses the descriptor exemption, a deliberate widening of the first draft's "other than `/dev/null`");
2. holds a `<(` or `>(` anywhere (a process substitution can read or write any file);
3. sits behind a hostile joiner (a pipeline, a subshell, a background job, `||`) or is itself a shell keyword (`if then else elif fi for while until do done case esac function`, `{`, `}`, `!`). This is the chain rule's test and it runs first, so the reason is the chain note (`is not certain to run`), not an invalidation reason;
4. is off the inert list below, or is on it with an argument that writes or expands: an argument that holds `$(`, a backtick, `$((`, `$[` or ends in `$` (a substitution can run anything), a masked `$(cat <<'D' …)` placeholder, one that *starts* with `-v` for `printf` (any argument, not only the first), or one that holds `${…=`, `${…:=` or `$((…=`, which assign. The whole pattern applies whether or not F names the assigned variable. Rule 4 also reads the redirections of every command from the writer through the reader: a redirect target holding such a substitution, and a statement heredoc whose body would expand (unquoted with `$`, a backtick or a backslash) or never closes, is a note (`<< an unquoted heredoc`); a here-string or literal heredoc with a plain target stays judged. A standalone assignment or `export` between writer and reader is off the inert list and unbinds, whatever the name.

**Before the writer.** Two shapes before the writer change what a later `cat` or `gh` does, so the binding reads every record before the writer too, with the reason `<F> may be rewritten or removed by <cause> before the heredoc`:

5. `_opens_descriptor`: an `exec`, found anywhere among the words of a record (so `{ exec >F; }`, `if …; then exec 3>F; fi`, `time exec 3>F`, `X=1 exec 3>F` and, as a fail-closed side effect, `echo exec > log` all count), or a `{NAME}` word, carrying a write redirect (rule 1's test, so `exec 3>&1` and `exec 2>/dev/null` are judged). The descriptor stays open onto F for the rest of the shell, so a later `>&3` writes F with no spelling in sight. Cause: `an open descriptor`. `_shadows` also unbinds on a function definition (`name() …` leaves `()` in the next record's joiner; `function name` as the command word), an `alias`, a `trap` whose actions after the handler are not all `EXIT` or `0` (cause `trap`), and a standalone assignment or `export` of a name that can change the writer `cat` itself (`PATH`, `LD_*`, `DYLD_*`, `BASH_ENV`, `ENV`: always), or of any steering name (`STEERING_NAME`: `GIT_*`, `GH_*`, `*PAGER`, `PATH`, `IFS`, `BASH_ENV`, `ENV`, `LD_*`, `DYLD_*`, `HOME`, `XDG_*`, `BROWSER`) only when a command sits between writer and reader. Keywords and wrappers in `LEADERS` (the shell keywords plus `time`, `command`, `builtin`) are skipped before the command word is read.
6. The `$'` guard: when an unquoted `$'...'` string appears anywhere in the command (`_Unrun.ansi_c`) and a record sits between writer and reader, the writer is unbound (cause `$'...'`): shlex reads `$'\''` differently from a shell and can hide a `; rm F` from every rule above.

**The chain rule.** A writer binds only if its execution is implied by the reader's (`_surely_ran`). The writer's own joiner must be the start, `;` or a newline (a sequential run with no `&&`), or every effective joiner from the writer to the reader must be a sequential run whose only operator is && (newlines allowed). In both cases no joiner from the writer through the reader is hostile, no record from the writer (exclusive) through the reader starts with a shell keyword, and the writer's own effective joiner is never hostile: `test -f F || cat > F <<D … D` then `&& gh pr create` does not bind, because the writer may be skipped. A writer after `test -d /x && cat > F <<D … D` and then a newline before the reader does not bind: if the test fails the writer is skipped while gh still runs. Joiners *before* the writer's own do not matter when the writer's own joiner is the start, `;` or a newline, because that command runs whatever the earlier ones did. A hostile run strictly before the writer, with a `;` or newline joiner for the writer, is therefore harmless. **Precedence:** the chain rule runs before the invalidation rules, so a keyword or hostile joiner between writer and reader always gives the chain note, never rule 3's or rule 4's reason (a first draft gave keywords the invalidation reason). A joiner is sequential only as one `;`, `&&` or newline followed by newlines; `;;`, `&& ;`, `; &&` and `|` are hostile. One over-match is accepted: the joiner concatenates every punctuation token, so `& &` (two tokens) reads as `&&`; bash rejects it as a syntax error, so gh never runs.

**What may sit between writer and reader (open question 2).** The binding survives an intervening simple command only if it is on this inert list, and it dies to any command not on it.

| Inert | Notes |
|---|---|
| `cd`, `pushd`, `popd` | dies for a relative F |
| `echo`, `printf` (without `-v`), `true`, `:`, `sleep` | |
| `cat`, `grep`, `egrep`, `fgrep`, `head`, `tail`, `wc`, `ls`, `test`, `[`, `diff`, `cmp`, `stat` | read-only verbs |

`rm`, `mv`, `cp`, `tee`, `sed`, `truncate`, `python3`, `git commit` and every other verb are off the list, and since the 2026-11-11 amendment so are every `git` and `gh` command and every standalone assignment or `export`: an earlier draft admitted the read-only `git` and `gh` forms and an assignment or `export` of a name F's spelling does not hold, and no corpus command used them. The PRD's `>`, `>>`, `rm`, `mv`, `tee` are all covered, and so is every verb nobody thought to name. Commands that follow the reader never matter: a cleanup after `gh pr create` does not unbind.

## Interfaces & contracts

### `preflight(payload_text, environ=None) -> (exit_code, stderr_lines)` (unchanged contract)

- Input: the PreToolUse payload. It reads `tool_input.command` and `cwd`, as today.
- Output: exit 2 with B's strings from `gates.pr_body_problems(text)` then the pointer line, when the hook read a body and B fails it; exit 0, silent, when it read a body B accepts; exit 0 with one `pr-body-preflight: not checked — <reason>` line per unreadable `gh pr create`.
- Failure modes: unchanged. Every exception after the payload parses is caught and becomes exit 0 with a note, so no exception escapes. Exit 2 comes only from a body the hook read exactly and B judged failing. Retry is safe: the hook has no side effects and the binding reads no file. Cost is one backward search and a constant number of passes over the compound's simple commands, linear. The binding itself does no I/O and imports nothing; a newly bound body does reach `_check_target`, which reads the cwd checkout's git config and calls `is_dir()` after a `cd` (see Accepted behaviour changes).

### `_bound_body(spelling, context) -> str`

- Input: the exact `--body-file` / `-F` value and the `context` mapping of the Data model (the splitter's `Simple` records for the whole compound, the reader's index among them, the capture's heredoc list and `ansi_c` flag). The first draft's `(commands, heredocs, position, spelling)` signature is superseded.
- Output: the file text a real shell leaves at that spelling when the compound runs up to the reader: the writer's heredoc text.
- Failure modes: raises `_Unreadable(reason)`. This is the open-question-1 answer: a binding the hook cannot establish is reported through the channel the hook already has, as a note, never as exit 2, and the caller needs no new case. The reasons, in the order the checks run, are:

| Situation | Reason in the note |
|---|---|
| F spells an expansion the hook cannot compare (checked first, with or without a writer) | `<F> names a file through an expansion the hook cannot compare` |
| F reaches the rule as `$` (an unquoted `$(…)` name) | `a command substitution names the body file, which the hook cannot compare` |
| no writer of that exact spelling anywhere earlier (a different file, a file from an earlier call) | `a body file is read only from the first command` (today's text) |
| writer found, delimiter line never closes | `the heredoc that writes <F> has no closing delimiter` |
| writer found, heredoc body holds `$`, a backtick or a backslash under an unquoted delimiter | `an unquoted heredoc body holds $, a backtick or a backslash` (today's text) |
| writer found, chain rule fails (including a keyword or hostile joiner between) | `the heredoc that writes <F> is not certain to run before gh pr create` |
| an unquoted `$'…'` in the command with a record between | `<F> may be rewritten or removed by $'...' between the heredoc and gh pr create` |
| a before-the-writer rule (an open descriptor, a function definition, `alias`, `trap`, `export` or `NAME=` of a steering name) | `<F> may be rewritten or removed by <cause> before the heredoc` |
| a write redirect or running redirect between them or on the reader, or a write redirect on a later closer (rule 1, the redirect part of rule 4) | `<F> may be rewritten or removed by <redirect> between the heredoc and gh pr create`, where `<redirect>` is the operator and target as written (`2> /tmp/b.md`, `<< an unquoted heredoc`) |
| an invalidating command between them (rule 4) | `<F> may be rewritten or removed by <verb or redirect> between the heredoc and gh pr create` |
| a relative F and a directory change between them | `a cd between the heredoc and gh pr create may change what <F> names` |
| `<(` or `>(` in the reader | `a process substitution in gh pr create hides the body file` (raised by `_body` before the binding) |

Known wart, a code item: a prefixed heredoc operator between writer and reader (`cat 3<<'X'`) names the heredoc placeholder in the note (`by 3<< __pr_body_preflight_heredoc_1__`); the verdict is right and the text is not (issue #1670, item 1).

The third row is why "a `--body-file` that names a different file" needs no row of its own: a reader whose spelling no writer wrote, and which the spelling rule accepts, is indistinguishable from today's not-first case and keeps today's note.

### The Verify replay and the false-block oracle (hand-off, with a recommendation)

- Input: one frozen file of unique `gh pr create` command strings; the pre-change hook (the merge-base commit's `pr_body_preflight.py`) and the changed hook.
- Output: for each hook, the count of commands exiting 2 or exiting 0 silently on a body it read, over the snapshot size; for each command judged through the binding, a verdict from `gates.pr_body_problems` on a reference body; and the survival funnel (see Decisions) beside the ceiling, so a miss of the 25% target names the rule that cost it.
- The reference body never comes from executing the Owner's command. Historical commands write absolute paths into real checkouts and run `rm`, `cp`, `python3` and `npm`, so running even their prefixes would overwrite real files. Instead the oracle builds the span from the **writer alone**: `cat > <scratch>` followed by the original heredoc operator and delimiter word, then the body and the delimiter line, found by regex over the raw command text independently of the hook's parser. Everything else on the operator's line (the rest of the command, a `&&` chain, other redirects) is dropped, and no other command of the Owner's is ever run. It runs that span alone under `sandbox-exec` with network denied, writes denied outside the scratch directory, a scratch `HOME` and an empty environment, with a per-span timeout (5 seconds); a span that times out is reported as *unpaired*, not as agreement. Variables in the span's body are unset, so an unquoted body with `$` is out of the criterion anyway. The span is paired with the hook's reader by the one heredoc whose redirect the hook reports as F's writer; a command whose text yields more than one candidate span, or none, is reported as *unpaired*, not as agreement.
- Failure modes: a refusal B would not give fails the run (PRD criterion 4). Known blind spot, recorded here and not papered over: this oracle checks the heredoc text, the writer shape and the pairing, not the commands between writer and reader, because it never runs them. A false block caused by the between-commands rule cannot show at Verify. The compensation is that Verify lists every bound command with at least one command between writer and reader and the Owner reads a sample by hand, and the inert list is the only thing the rule trusts.

## Accepted behaviour changes

Compared by running the old rule (a body file is read only from the compound's first word-bearing simple command; a `<(` is read as a redirection that drops the next word) and the new rule over the inputs where they differ. Exit codes differ only in the first row; the others change stderr.

| Input class | Old | New |
|---|---|---|
| not-first `--body-file F`, bound by a `cat > F <<D` that passes every rule | note, exit 0, unjudged | judged: exit 2 if B fails the heredoc text, exit 0 silent if B accepts it |
| not-first `--body-file F`, a writer exists but a rule fails | `a body file is read only from the first command` | the reason from the table above (stderr changes; exit 0 as before) |
| as the first row, bound, but the compound `cd`s the checkout out of this repository or to a place the hook cannot place | the first-command note | the `_check_target` reason (`a cd before gh pr create leaves this repository` or `… the hook cannot place`); exit 0 as before |
| `-F <(…)` or `-F >(…)`, as the first command or not | first: the first word after `<(` was read from disk as the body and judged, a refusal B might not give; not-first: the first-command note | `a process substitution in gh pr create hides the body file`, exit 0 (a first-command case that was a latent false block is now a note) |
| a leading redirect-only command (`> log`) | not a command; `first` unaffected | a record for the binding walk only; `first` and `position` are computed over records with words, so the result is unchanged |
| no writer of F in the compound; first-command file; inline `--body`; `$(cat F)`; every other fail-open | as today | identical output for a spelling the hook can compare. A not-first `-F` whose spelling it cannot compare (`$PWD/b.md`, `~/b.md`, `$(mktemp)`, a glob) with no writer now gives the expansion note where it gave the first-command note (exit 0 either way) |

New I/O, stated once: the binding reads no file. A newly bound body is judged only after `_check_target` passes, and `_check_target` reads the cwd checkout's `.git/config` (following a worktree's `gitdir` and `commondir`) and calls `is_dir()` for each `cd` argument. Those reads are the hook's existing ones, reached by more commands, and every failure there is already a note.

- Accepted limit: if the writer itself fails (an unwritable directory, a full disk), gh reads whatever the file held, not the heredoc. The hook still judges the heredoc text. A body B would accept on disk is refused only if the writer failed and a stale passing file was there; that needs two coincidences and the refusal asks only for a body fix.
- Accepted limit: `'$S/x'` (single-quoted, a file literally named `$S/x`), `$'...'`, `$"..."` and `"$S/x"` tokenize alike. Both ends would have to be spelled differently for this to bind wrongly.
- Accepted limit: substitutions in the reader's own arguments are trusted: a `$(…)` or backtick in `gh pr create`'s other arguments is not read as a writer of anything, and the `-F -` (stdin) check stays ahead of the binding, so `--body-file -` after a writer of any spelling is the stdin note, never a bound body.
- Accepted limit: a command on the inert list is trusted to leave F alone unless its arguments or redirects write. The list names only commands whose arguments the rules read.
- Accepted limit (review finding 4): a leading redirect-only command that truncates F, then `gh pr create -F F` as the first word-bearing command (`> F`, a newline, then the reader). The hook reads the file on disk, which may be a stale passing file, while the shell has already emptied it, so CI's B refuses what the hook let through: an under-block, never a false block. Decided as an accepted limit, not a code change. The alternative, demoting `first` when a leading word-less record carries a write redirect that is not `/dev/null`, regresses `> log` then `gh pr create -F x.md` (finding 10, pinned by `test_a_log_redirect_before_a_first_command_body_file_reads_from_disk`) unless the hook compares `log` with F's spelling, and comparing spellings is the thing the invalidation rules refuse to do (`./F` for `F` and `$BODY` slip past a comparison). The choice is therefore between a false demotion of a common shape and a miss on a shape nobody writes (an agent truncates a file in order to read it); the miss costs a red CI check and the correction is a body fix. `docs/kb/pr-body-contract.md` says it in one sentence.
- Accepted limit: things that run or change the shell in ways the rules do not read, before or between writer and reader: `eval` and `source` (they run text the hook cannot read), `declare -x`, `typeset` and `readonly` of a steering name, `export PATH=/x FOO`, `for PATH in`, `PATH+=`, `unset PATH`, `set -o` and `shopt` options, `enable -n` and `hash`. Each is an under-block that needs the writer, the reader and the stale file all to line up; none is a false block.
- Known imprecision in the `trap` and leading-assignment reading, routed as code items (issue #1670, items 3 and 4): a trap on `INT`, `TERM` or `HUP`, `trap -p` and a leading `--` are notes where a shell would run nothing harmful (a missed judgment, never a false block), and a leading assignment before the command (`X=1 trap … DEBUG`, `X=1 alias …`) before the writer is judged though it should unbind (an under-block).

## Decisions & alternatives

- **The binding lives inside `pr_body_preflight.py`, as one new function fed by two extended records** over a new module (`heredoc_binding.py`): the rules need `_Unrun`'s heredoc bodies and the splitter's redirections, so a separate module would have to import both or be handed them, and exposes the parser's internals for one caller. Deleting it would not remove complexity from the hook, only move it. Answers open question 1. Standards: `stdlib-only`. Confirmed by the Owner.
- **A binding it cannot establish is an `_Unreadable` note** over a new return type (`Bound | Unbound(reason)`): the hook already routes every unreadable body this way, and a second channel would be a second case in `_verdicts` for no new fact.
- **F is matched by spelling identity, never resolved to a value** over a variable table (`S=<dir>` then `$S/b.md` expanded) and over binding literal paths only. The probe's funnel below shows a literal-only rule binds 222 of 1817 (judged share 20.9%) against spelling identity's 323 (26.5%). A table resolves values the hook cannot know (`$TMPDIR`, a value with `$(mktemp)`), and identical spelling in unchanged state names the same file without knowing them. Confirmed by the Owner.
- **Invalidation never compares spellings, and what may sit between writer and reader is an inert allowlist** over a deny-list of `>`, `>>`, `rm`, `mv`, `tee`, and over an invalidation keyed on F's spelling. Binding may rely on identical spelling (a mismatch there only falls back to a note); invalidation may not (a mismatch there keeps a stale binding: `./b.md` for `b.md`, a `$BODY` alias, `>> "$BODY"`). A deny-list passes every verb nobody listed (`sed -i`, `cp`, `python3`), and each is a refusal B would not give. Any file-writing redirect, any `<(`, any hostile joiner and any command off the list unbinds. Answers open question 2. Confirmed by the Owner.
- **The chain rule: the writer's own joiner is the start, `;` or a newline, or every joiner from writer to reader is `&&`; no joiner from writer to reader is hostile** over "every joiner from the compound's start to the reader is sequential". The second is wrong where `test -d /x && cat > F <<D … D` has a newline before the reader: the writer is skipped when the test fails and gh still reads the stale file. A hostile run before a `;`-joined writer is harmless, since that writer runs whatever came before. The cost is in the funnel: 102 writers in the probe sit after a `&&` with a newline before the reader (`cd "$D" && cat > F <<EOF … EOF`, newline, `gh pr create`).
- **The chain note outranks the invalidation reasons** over giving a keyword rule 3's reason: a keyword or a hostile joiner between is one fact (the writer's execution is not implied), and the Implementer's chain test runs first because the Milestone 2 Accept line names "an `if` between" under that reason. Recorded here so the two documents agree (issue #1664, item 3b).
- **Inert assignments die on steering names, not only on names F's spelling holds** over killing only the names F holds: a `PATH`, `GIT_*`, `*PAGER`, `HOME` or `BROWSER` assignment changes what the next `git` or `gh` does without naming F. Stricter than the first draft and always toward a note; `export PAGER=cat` is therefore a note. Since the 2026-11-11 amendment no assignment is inert between writer and reader (every one is a note), so this decision now governs only an assignment or `export` before the writer (`_shadows`, with `STEERING_NAME`).
- **Descriptor-prefixed redirects are told from a command word in `_Unrun`, not in the splitter** over a splitter that sees only tokens: shlex cannot tell `2>&1` from `2 >&1` once the whitespace is gone, so the marker word is the only way to keep `2>&1` judged, as the breakdown's Accept line says. The Milestone 3 code first made a bare `2>&1` a note; the Milestone 4 follow-up restored it (issue #1667, item 1) and the `/dev/null` and read exemptions with it.
- **A leading truncating redirect is an accepted limit, not a demotion** over demoting the first command: see Accepted limits, review finding 4.
- **The path is judged with no disk read and no cwd** over reading the file the heredoc just wrote: the file does not exist yet at hook time, which is the whole problem.
- **A heredoc's index is carried by a placeholder word in the token stream, and bodies are unmasked on capture** over counting `<<` operators in two places and over skipping masking inside heredoc bodies. Counts diverge on `"$( … <<A )"`, `X=$(… <<A)` and `<<<`; a placeholder in the target position cannot.
- **The replay snapshot is a local, uncommitted file and only its SHA-256 and count are recorded in `verification.md`** over committing the corpus: the commands carry PR bodies from the Owner's private repositories. Frozen means one sorted, de-duplicated JSONL file written once, at the start of Verify, outside the repository (the Owner picks the path); both the baseline and the changed hook run over it, and `verification.md` records the extraction command, the count, the SHA-256 and each measured number so a rerun on the same file reproduces them. The replay harness is a throwaway script, not a repository tool. Answers open question 3 as a recommendation; the Owner confirms at Verify.
- **`--body "$(cat F)"` after a same-call writer keeps today's note** over binding it too: the PRD names `--body-file`, and it is a separate spelling that the replay did not count.

### The 25% criterion and the survival funnel (a rough probe, not the Verify measurement)

The probe ran the tightened rules through the real tokenizer over the 1817 re-extracted commands. Of 1064 not-first body-file readers, 548 name a file that a `cat >`-style writer wrote earlier in the same command. Survival:

| Stage | Lost | Left |
|---|---|---|
| writer names F | | 548 |
| spelling rule | 4 | 544 |
| writer shape (`printf`, `sed`, `{ … } > F` and similar are not heredoc writers) | 58 | 486 |
| unquoted heredoc holding `$`, a backtick or a backslash | 22 | 464 |
| chain rule: a writer behind `&&` with a newline before the reader | 102 | 362 |
| chain rule: a `|`, `(`, `)` or lone `&` between | 26 | 336 |
| between-commands rule (off the inert list: `python3` 11, `gh` 2) | 13 | 323 |

So **323 bind**: a judged share of (158 + 323) / 1817 = 26.5%. Two further figures bound the criterion: binding every writer with no rule at all gives (158 + 548) / 1817 = 38.9%, and the writer-behind-`&&` rule alone costs 102 commands, 5.6 points. A relaxation, not adopted because the Owner asked for the stricter rule, lets a writer behind `&&` bind when everything before it in that `&&` run is `cd`, `pushd`, `export` or a plain assignment: it binds 410 (31.3%). **On this probe no rule set reaches 40%, the target before the Owner's decision**, and the gap to #1633's ceiling (839) is the 681 against 548 difference, which the probe cannot explain. This is not a design failure to hide: the PRD already requires Verify to re-derive the reachable ceiling on its own snapshot and report it beside the 25% result. Recommended Verify report: the funnel above, row by row, on the frozen snapshot, beside the ceiling and the share, so a miss names its cause; if the re-derived share misses 25%, the Owner decides with that table in hand whether to take the relaxation or revisit the target.

**Measured (Verify, `verification.md` criterion 3):** 479 of 1817 snapshot commands judged, 26.36%, against the 25% target (455 needed, margin 24), up from 229 (12.60%) for the pre-feature hook, with 307 readers bound and 250 of them judged after the hook's own target check stopped 57 (a `cd` the hook cannot place, or another repository). The margin depends on the disk of the day (19.15% with no cwd in any payload). The funnel gained rows the probe's table lacks: the target check after binding, and the before-the-writer rules and the `$'` guard, which lose nothing on that corpus.

**Decision (Owner, 2026-11-09):** the target is lowered from 40% to 25% and every safety rule above is kept. Reason: the safe design's probe share is about 26.5%, and #1633's 681 same-call count was not reproduced (the probe found 548). The PRD's criterion is amended to match. idea.md's 40% ("Success in one sentence") is superseded; idea.md is a historical artifact and is left unedited.
